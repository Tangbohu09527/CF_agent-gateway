## 本提交实现

新增纯函数 `parse_inbound_media`，仅规范化入站 file/image 响应，不进行网络、磁盘、数据库或模型调用：

- `pending`、`unsupported`、实际有内联字节的 `ready` 独立表示。
- 本轮实际出现的无 data 的 pending 是有效状态，而不是误报“成功取得文件”或笼统JSON错误。
- 无数据的 file/image、类型冲突、上游错误、无效/超限 Base64 分别拒绝，错误信息不回显输入。
- 解码前后限定字节上限。调用方仍须在 HTTP 接收阶段限制整个响应体；此函数不能限制已经分配的JSON对象。
- URL返回必须走另行审查的契约，本模块不跟随URL，也不把地址当原件。
- 图片 quality 只记为上游声明。只有独立提供的期望大小与SHA-256同时匹配，才报告原件对比一致；响应自己声明的哈希不能自证原件。
- 数据可用但与原件期望不同仍明确报告 `different`，不是网络错误，也不能当原图归档。
- 文件名只作为元数据，不直接拼接存储路径；安全摘要和repr不含文件名、正文或Base64。

`READY` 只表示取到了字节，**不表示已持久化、已授权、已上传FileBrowser或可安全打开**。文件头识别不是完整PDF/图片结构校验，更不是恶意内容扫描。自动归档还需要来源绑定、准入、内容校验和持久化记录。
