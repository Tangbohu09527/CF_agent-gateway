# 微信工作台实时与受控操作候选

接续 PR26，保留聊天、通讯录、群和员工权限布局。新增后台仅归档采集、持久增量游标、微信在线灯、分层系统状态、AI 主机向导和固定服务控制入口。部署与现场结果以本目录的最终交付记录为准；合成浏览器结果不代表真实微信验收。

## 采集和增量

`management_console/live.py` 使用既有 WeChat normalizer、事件标识、`MessageStore` 和消息表。它没有准入、Hermes Dispatch、Delivery 或附件原件下载依赖。普通未授权消息和自发消息可以留档；这不会授予发言人权限。数据库迁移 `20261021_02` 仅增加候选观察、归档控制和增量日志表，不回填员工或历史数据。

正式 PostgreSQL 档案继续通过强制只读连接读取。候选的新消息写入独立候选数据库的同一消息模型，查询时合并只读历史；事件标识去重覆盖整个候选分区，分页总数不按当前页猜测。员工、群、节点、权限和既有会话配置均保留。

启用前要求管理员明确选择仅归档，并通过固定 Controller 确认原 Poll 容器已退出。控制通道未知或原 Poll 恢复运行时，候选停止新增采集并显示受阻；不会替用户停止正式 worker。文件锁只解决候选多进程竞争，外部来源所有权另外检查。

首次可见窗口只记录身份基线，不导入旧消息、不倒退或清除正式 checkpoint。此后采集近期非隐藏会话的最新 200 条窗口。新发现的旧会话、上游窗口溢出、停采和手机历史仍可能有缺口；不能称完整历史恢复。采集由服务器后台线程运行，关闭网页不停止它。

持久递增日志 ID 独立于消息时间，支持同秒、迟到和乱序到达。只有消息入库后才记录通知；中间退出后重复观察可幂等补全通知。游标绑定来源和 Bot 账号，前端在应用增量后推进游标，断线继续补齐。列表局部更新，阅读历史保留位置并显示新消息提示；切源与退出丢弃旧请求结果。网页阅读不改变微信未读。

## 在线灯与系统状态

绿灯来自未过期的 `/api/status/auth` 实际进程/FSM 认证观察；红灯来自明确未登录、失效或进程未运行；请求失败、无法判断和 20 秒过期为灰。该 GET 在上游会保存观察状态，不会打开聊天、扫码、切换账号或发送消息。安静的聊天不视为离线。灯只证明微信登录状态，采集、派发、投递和存储分别展示。

正式档案的 Dispatch/Delivery 分状态计数由后台每 15 秒只读聚合并缓存，展示来源和时间，不将累计完成数量称为正在运行。Controller 只读观察独立显示 Poll/Dispatch/Delivery 容器状态；主动停用和未知分别标注。文件服务无接口可证的空间、挂载和可写性显示未采集，不持续写正式文件。AI 节点业务与管理连接分别检查，见 [节点契约和教程](nodes.md)。

## 固定受控入口

原 `deploy/wechat-runtime-control` 的 start 会启动 Poll 与 Delivery，因此本候选不调用它来“全部启动”。新 `deploy/wechat-console/control.py` 复用其固定角色与身份核对原则，仅增加本轮必要的 Unix socket 动作：

| 动作 | 边界 |
| --- | --- |
| `GET /status` | 检查固定微信容器及三个固定 worker 的状态，不启停 |
| `POST /wechat/start` | 精确镜像身份匹配才启动已经存在的微信容器；已运行直接保留 |
| `POST /wechat/app/start` | 仅支持已现场核验的固定 supervisor 程序；未验证则拒绝，不猜命令 |

Web 只挂该 socket 目录，无 Docker socket、sudo、通用命令或任意目标参数。控制配置必须 root 所有且不可由 Web 修改；Unix peer UID/GID 经过检查。每个可控来源必须显式绑定该物理服务。动作沿用管理员鉴权、Cookie、CSRF、同源保护与脱敏审计；HTTP 200 内的 failed/unsupported 仍显示失败。

部署单元和可选 Compose overlay 在 `deploy/wechat-console/`。控制器需要宿主预先运行 Docker 和最小管理基础；Web 不能给关机宿主或自己开机。此轮不修改旧 Controller 的 worker 闸门，不自动启动正式业务。

## 登录保留边界

固定上游 `thisnick/agent-wechat@96c2e90c497d999bf5189a134a9b3b293731f42e` 的 `router/status.rs` 和 `plans/login.rs` 显示：`newAccount=false` 不主动切号，但发现不同账号时登录计划可能先清会话数据。`LoginWsParams` 尚无 `expectedAccount` 守卫。因此当前官方入口不能仅靠 Gateway 收到 success 后再核对账号来保证不清旧数据。

候选保留了单来源、180 秒超时、重复操作复用、二维码仅内存、手机确认、重新核对认证/账号/联系人等编排。目标必须在认证后的真实状态响应中声明 `expected-account-v1`、必填预期账号及不符时保留会话，且观察未过期、operator 明确允许，才启用扫码动作；单独配置标记不能开启；本轮不把未知目标设置成支持。已在线始终保留，不为演示故意退出。未修改或替换正式微信核心镜像；需要上游最小保护补丁时另做组件变更及生产切换许可，不能调用旧 fresh-QR 脚本绕过此边界。

## 使用与验证

正式候选地址、实际运行源码、备份和停止命令以最终交付记录为准。已有登录不重设。当前候选授权与正式员工权限继续隔离；页面标注“正式权限未核验”和“尚未作用于正式派发”，不会因候选未关联而宣布正式已拒绝。

自动化入口：`pytest tests/management_console`；实际页面验收分别为 `browser.cjs`、`nodes_browser_runner.py`、`live_browser_runner.py`。Linux 固定控制器 smoke 只在一次性 CI runner 中对带本任务标签的网络隔离合成容器执行真实 Unix socket/inspect/start；不接真实微信。模型和微信替身、官方 Profile 验证、现场验收各自记录，不互相替代。

Windows `scripts/wechat-console/start.ps1`、`stop.ps1` 和 Profile B BOM 修正保留。用户无需靠 Windows 终端维持 CFserver 候选。所有公开截图必须是合成资料；真实联系人、聊天、二维码、连接配置和长期密钥不得加入仓库或 CI 制品。
