```text

    -> agent-wechat
```

## Outbound contract correction

The verified external endpoint is:

```text
POST /api/messages/send
```

The request body uses `text`, not `content`:

```json
{
  "chatId": "<conversation-id>",
  "text": "<assistant-text>"
}
```

The Gateway implementation and its regression test use this contract.

## Self-message echo protection

An assistant reply sent through `agent-wechat` can appear again in a later polling result
with `is_self=true`. The V1 polling layer handles that raw message as follows:

- do not normalize or deliver it to the sink
- do not enter Message Store through the polling path
- do not run identity resolution or permission admission
- do not call Hermes
- advance the conversation checkpoint

Advancing the checkpoint prevents the reply from being examined on every later poll. If
the checkpoint write fails, the next poll may examine and skip the same self message again.
Eligible non-self messages retain the at-least-once sink-delivery contract.

## Group-thread design deviation

The target group-thread key remains:

```text
bot_account_id + group_chat_id + sender_id
```

The current V1 implementation instead binds an AIThread to the source account and physical
conversation. Authorized senders in the same group therefore reuse one whole-room thread,
although each sender is still independently identity-resolved and permission-checked.

This is a known implementation deviation, not a target-design change. The Staging result
records the behavior that was exercised; it does not approve the deviation. Correcting it
requires a separate reviewed code, schema, migration, and regression-test change.

## Explicitly outside the validated scope

The following capabilities must not be described as implemented or Staging-validated:

- image understanding
- image attachment delivery to Gateway or Hermes
- file-message processing
- OCR
- archive or ZIP parsing
- enterprise knowledge base
- automatic Skill execution
- production automated deployment

The adapter contains limited media retrieval and message-type foundations, and Message
Store has attachment metadata models. Those foundations do not form an attachment or file
processing pipeline. The repository Compose service starts the HTTP application only; it
does not constitute automated production deployment of the resident Worker.

## Known delivery boundary

Message Store idempotency and checkpointing make inbound storage retries safe. Hermes
dispatch and outbound response delivery do not yet use a durable outbox or an upstream
idempotency key. An ambiguous external result can therefore require operational review and
must not be represented as production-grade exactly-once delivery.
